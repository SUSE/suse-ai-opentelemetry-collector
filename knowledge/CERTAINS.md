# Verified collector facts

Verified on 2026-09-09 on `fix/collector-v0.160.0-release`, based on `5051b297812af3fb54c8503f016fa25d6cd72750`, including the authorized fixes and release preparation. See [post-fix validation](validation-2026-09-09.md) for results and limits, and [the historical audit](audit-2026-09-09.md) for the original defects.

- The topology-retention branch is already merged into `main` through PR #26.
- GitHub showed no open PRs before this release-preparation PR. PRs #25, #28, and #31 were already merged. Dependabot closed #32 and #33 as superseded: the generated collector already requires gRPC v1.83.2 and Thrift v0.24.0.
- The latest upstream collector release checked on 2026-09-09 is [v0.160.0](https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.160.0). This repository's latest published release is v0.156.0; v0.160.0 is unused and is the intended next release tag.
- The builder manifest sets distribution version `0.160.0`, the updater derives it from the selected release tag, and the regenerated executable reports `suse-ai-opentelemetry-collector version 0.160.0`. The prior empty version made `--version` unavailable. A seventh integration test checks the binary against the manifest.
- The generated collector uses OTel components v0.160.0 and declares Go 1.26.0. The container and CI now use Go 1.26.7. The amd64 container builds successfully and validates its packaged configuration as user 10001.
- The local release candidate `suse-ai-otelcol:0.160.0-candidate` has image ID `sha256:6c80f416ccb7db66f5c372d9a86f5a39aee6f5923f12eea61db309110311440c`. Its packaged configuration is byte-identical to the working configuration, and `--version` reports `0.160.0`. This image has not been published or deployed.
- Seven integration tests pass against the binary extracted from that image. They verify the distribution version and exercise actual OTLP ingestion and Prometheus scraping with localhost fixtures. Kubernetes discovery/enrichment, the Elasticsearch API, and downstream synchronization require separate deployment verification.
- The topology exporter's race tests pass in its own module, under the checked-in collector dependency graph, and under the regenerated v0.160.0 graph. `go vet ./...` also passes.
- The shipped configuration passes the actual collector's `validate` command. It retains health checks, Jaeger ingestion, deployment variables, and legacy attribute compatibility from the draft. It uses standard resource telemetry instead of the draft's synthetic topology pipelines.
- The topology stream identity is fixed to instance type `suse-ai` and URL `collector`. `cluster_name` is an optional metadata label, not a stream identifier.
- Traces without Kubernetes metadata are exported. Original trace/span IDs, service identity, host identity, and canonical GenAI values are preserved. Original telemetry has one export path; the span-metrics connector separately emits `otel_span.*` measurements.
- GenAI promotion fills missing resource attributes. Distinct models append to `gen_ai.models` within each resource batch, preserving existing entries and distinguishing model-name prefixes. This is not persistent inventory across batches.
- Prometheus fixtures verify service/namespace context and standard GenAI/DB identity for vLLM, Milvus, and Qdrant. Two vLLM targets retain distinct instance IDs, native metric names, and histogram buckets. GPU resources carry `hw.type=gpu`.
- The optional topology exporter encodes API keys, masks configuration values, and omits credential-bearing URLs from transport errors. A refused-connection probe using the packaged binary produced no synthetic key or `api_key=` in its log.
- The topology HTTP client defaults to a 10-second timeout. Requests honor cancellation, shutdown cancels and waits for the periodic loop before a bounded final flush, and redirects are rejected. Deadline and shutdown behavior have regression coverage.
- Publication paths include collector configuration and exporter changes. A new validation workflow builds, runs race tests, and exercises telemetry behavior. The updater uses matching release-tag manifests, builds and validates the result, and checks the container Go version. An isolated update to v0.160.0 passed.
- The unstripped audit binary scan with `govulncheck` v1.8.0 reports zero affected symbols or imported packages and five module-level advisories. The stripped image binary causes the scanner to fall back to module-level precision. The audit binaries and versioned release candidate have the same 509 dependency module versions; the affected SSH, OpenPGP, and S3 crypto packages are absent from the collector's dependency-package list.
- Live topology synchronization was not verified: the configured local SUSE Observability endpoint refused the CLI connection.
