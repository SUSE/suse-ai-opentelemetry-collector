# Collector audit, 2026-09-09

This is the historical baseline audit, before the user authorized fixes. The findings and draft references below describe that baseline. See [post-fix validation](validation-2026-09-09.md) for the implemented corrections and current verification results.

Recommendation: **do not integrate the uncommitted collector configuration as a whole.** Health checks, Jaeger ingestion, configurable deployment values, and the compatibility mapping from `db.system.name` to `db.system` are candidates for a smaller change. The new topology and relation pipelines need redesign to preserve standard OTel telemetry and follow the resource-based strategy in `AGENTS.md`.

Findings are ordered by severity. References to draft line numbers refer to the preserved working `collector-config.yaml`; upstream line numbers refer to the same file at `5051b29`.

1. **P1: container publication is broken on main.** [Containerfile](../Containerfile), lines 1 and 8–9, uses Go 1.25.5 with builder v0.160.0, which requires Go 1.26.0 or newer. The Rancher image sets `GOTOOLCHAIN=local`. Both architecture jobs in [run 34398523456](https://github.com/SUSE/suse-ai-opentelemetry-collector/actions/runs/34398523456) failed at the builder installation for this reason. Use a verified Rancher Go image meeting the builder requirement and align the documented build requirements. A successful local build on Go 1.27.1 does not validate the current Containerfile.

2. **P1: the draft cannot start.** Draft line 329 sets `topology.instance_url`, removed when the topology stream identity became constant. The actual compiled collector rejects the configuration with `topologyexporter.Config has invalid keys: instance_url`. Removing only that key in a temporary copy makes full configuration validation pass. `cluster_name` is the supported field for the cluster metadata label; the draft currently does not set it. [Exporter configuration](../topologyexporter/config.go), line 21.

3. **P1: the draft silently drops valid traces lacking Kubernetes metadata.** Draft lines 194–201 and 351 apply `filter/dropMissingK8sAttributes` before every trace output. Any missing node name, pod UID, namespace, or pod name drops the span. In a local probe, both two-span traces were accepted over OTLP with HTTP 200, but only the trace containing all four Kubernetes attributes reached outputs. The otherwise identical application trace without those attributes disappeared. This affects external applications and applications whose enrichment is unavailable. Keep the standard trace path independent of topology enrichment requirements.

4. **P1: the draft sends conflicting copies of the same spans to one backend.** Draft lines 362–370 export the original trace IDs and span IDs from two relation pipelines in addition to the sampled trace pipeline. The probe produced three copies of each surviving GenAI span. One copy changed `service.name` from `audit-app` to `ollama` or `anthropic`; another changed `peer.service`. The Ollama span's provider relation incorrectly pointed to `anthropic`, the last provider promoted to the shared resource. These relation outputs also bypass tail sampling. Preserve span identity and original attributes; derive topology from resource context in the StackPack rather than exporting rewritten copies as ordinary traces.

5. **P1: resource promotion loses identity and model information in both versions.** Upstream lines 84–86 and draft lines 121–122 overwrite existing resource values on every span. A resource with provider `resource-provider` and models `existing-model`, followed by calls to `ollama/llama3` and `anthropic/claude`, left the pipeline with provider `anthropic` and models `claude`. Neither earlier model remained. This contradicts the explicit missing-only promotion and comma-separated model aggregation requirements. The resource processor also overwrote `service.namespace=tenant-a` with the collector's configured namespace, and the system detector replaced `host.name=workload-host` with the collector host. Use missing-only promotion, real model aggregation, `override: false` for resource detection, and namespace defaults that preserve supplied identity. [Draft resource processors](../collector-config.yaml), lines 86–89 and 131–144.

6. **P1: the existing topology exporter exposes its API key in failure logs.** [receiver_client.go](../topologyexporter/receiver_client.go), lines 38–47, puts the key in the URL and returns the transport error unchanged. [exporter.go](../topologyexporter/exporter.go), lines 79–82, logs that error. A local connection-refused probe logged the synthetic `api_key=audit-canary-not-a-real-key`. Redact credentials from errors, encode query parameters correctly, and use header authentication if supported by the receiving API. This exporter is disabled in the upstream default configuration and enabled by the draft.

7. **P2: infrastructure resource heartbeats lack standard system identity.** Local Prometheus probes exercised the `vllm`, `milvus`, and `qdrant` jobs through each version's metric processor chain. All three exported resources lacked `gen_ai.system`, `gen_ai.provider.name`, `db.system`, and `db.system.name`. The draft adds only `suse.ai.*` classifications. A raw scraper cannot supply attributes that no relabeling or processor creates. Populate the relevant standard system attributes per scraper resource and preserve target identity. The draft also replaces every vLLM `service.instance.id` with the constant `vllm` at line 156. Backend delivery to `sts_topo_opentelemetry_collector` remains unverified; the enabled custom topology export uses the separate fixed `suse-ai/collector` stream.

8. **P2: inferred metrics bypass normalization and duplicate measurements.** Draft lines 382–395 receive OTLP metrics directly, independently of the normalization in the main metrics pipeline. A `gen_ai.client.token.usage` point with `gen_ai.system=ollama` was exported from four pipelines. The provider-inference copy retained `service.name=audit-app` and had no `gen_ai.provider.name`, so it did not discover the provider. The model copy changed the service identity and removed the model datapoint dimension through grouping. Normalize before any inference, and avoid sending copies of real usage measurements as synthetic component heartbeats to the same backend.

9. **P2: the topology HTTP client has no deadline and ignores shutdown cancellation.** [exporter.go](../topologyexporter/exporter.go), line 48, creates an HTTP client without a timeout; [receiver_client.go](../topologyexporter/receiver_client.go), line 39, creates a request without context. Shutdown performs another synchronous flush at exporter lines 91–94 without waiting for an in-progress periodic flush. A local receiver that accepted the request but withheld its response kept shutdown blocked past the probe's three-second observation window; the collector exited only after the receiver was released. Add bounded requests and coordinate the flush loop and shutdown.

10. **P2: source changes can miss publication and the updater can mix releases.** [publish-container.yml](../.github/workflows/publish-container.yml), lines 7–11, excludes both `collector-config.yaml` and `topologyexporter/**` from its push paths even though the image copies both. The final dependency update at `5051b29` did not trigger an image build. Add those paths and the workflow itself, plus pull-request build/configuration checks. [update-collector.sh](../scripts/update-collector.sh), lines 6 and 12–13, chooses a released builder but fetches component manifests from moving upstream `main`; fetch manifests from the selected release tag and fail on HTTP errors. The update workflow regenerates without compiling, so it does not establish image-build or runtime-configuration compatibility.

Additional maintenance observations: the README still specifies Go 1.24+ and builder v0.147.0, while the generated collector module requires Go 1.26.0 and the manifest uses v0.160.0. ShellCheck reports SC2034 for the unused `VERSION_NO_V` and SC2046 for the unquoted builder path in `scripts/update-collector.sh`. These are secondary to the build and telemetry defects.
